# Paperless-NGX SSO + User Provisioning

**Date:** 2026-05-30  
**Status:** Approved

## Context

Paperless-NGX is already deployed (`docs.{domain}`) and has its OIDC configuration declared in `docker-compose.yml`. The portal has a working `/dashboard/docs` tab. `PaperlessService` already creates Paperless accounts + mail rules + workflows when admins provision users.

The gap: the Authentik OIDC provider for Paperless was never created during bootstrap. `PAPERLESS_OIDC_CLIENT_SECRET` is empty in `.env.example` and never generated by `install.sh`. As a result, SSO login to Paperless fails entirely.

## Goals

1. Fix Authentik bootstrap to create the Paperless OIDC provider and application
2. Generate `PAPERLESS_OIDC_CLIENT_SECRET` (and `PAPERLESS_SECRET_KEY`) during install
3. Allow the already-running live system to provision the missing provider without a full re-bootstrap
4. No changes to user provisioning (already correct) or portal nav (already correct)

## Architecture

### Secret generation — `install.sh`

Add to the generated `.env` block:

```bash
PAPERLESS_OIDC_CLIENT_SECRET=$(gen)
PAPERLESS_SECRET_KEY=$(gen 64)
```

`PAPERLESS_SECRET_KEY` is the Django session key (was previously empty). Both are only written if `.env` does not already exist (existing guard in install.sh).

### Authentik provisioning — `api/src/bootstrap/integrations/authentik.service.ts`

Extend `AuthentikConfig` interface:

```typescript
paperlessOidcClientId: string;     // typically 'paperless-ngx'
paperlessOidcClientSecret: string;
```

Add two idempotent methods called at the end of `provision()`:

**`createPaperlessOIDCProvider(api, config)`**
- Checks for existing provider named `paperless-ngx`; returns its pk if found
- Creates OIDC provider with:
  - `name: 'paperless-ngx'`
  - `client_id: config.paperlessOidcClientId`
  - `client_secret: config.paperlessOidcClientSecret`
  - `client_type: 'confidential'`
  - `redirect_uris: 'https://docs.{primaryDomain}/accounts/oidc/paperless-authentik/login/callback/'`
  - `sub_mode: 'hashed_user_id'` (consistent with portal provider; Paperless uses `preferred_username` from userinfo, not sub)
  - Same `authorization_flow` as the portal provider

**`createPaperlessApplication(api, providerId, primaryDomain)`**
- Checks for existing application with slug `paperless-ngx`; skips if found
- Creates application:
  - `name: 'Paperless'`
  - `slug: 'paperless-ngx'`
  - `provider: providerId`
  - `meta_launch_url: 'https://docs.{primaryDomain}'`

### Bootstrap wiring — `api/src/bootstrap/bootstrap.service.ts`

In `runBootstrapPipeline()`, extend the `authentikService.provision()` call:

```typescript
paperlessOidcClientId: process.env.PAPERLESS_OIDC_CLIENT_ID ?? 'paperless-ngx',
paperlessOidcClientSecret: process.env.PAPERLESS_OIDC_CLIENT_SECRET ?? '',
```

### Admin re-provision endpoint — live system fix

Since bootstrap has already completed on the live VPS, add:

**`POST /api/admin/reprovision-authentik`** (internal secret guard, admin role)

- Reads all Authentik config from env vars
- Calls `authentikService.provision()` with full config
- Safe to call on a READY system — all provisioning methods are idempotent
- Returns `{ ok: true }` on success

Add to `admin.controller.ts` and `admin.service.ts`. The service method reads config from `ConfigService`/`process.env`.

## Data Flow: First Paperless Login

1. User clicks "Documenten" in portal → opens `https://docs.{domain}`
2. Paperless redirects to Authentik: `https://auth.{domain}/application/o/authorize/`
3. Authentik authenticates user (existing session or login form)
4. Authentik redirects back: `https://docs.{domain}/accounts/oidc/paperless-authentik/login/callback/`
5. Paperless creates user account via `PAPERLESS_SOCIAL_AUTO_SIGNUP=true`
6. User lands in their Paperless inbox

For pre-provisioned users (admin-created): account already exists in Paperless via `PaperlessService`; SSO login attaches to the existing account by username match.

## User Provisioning (no changes)

`PaperlessService.ensureUserAndWorkflow()` is already called from `UsersService` when an admin creates a platform user. It:
- Creates Paperless user account via REST API
- Creates consume-folder workflow scoped to that user
- Creates IMAP mail account + mail rule for email-to-document

No SCIM protocol is implemented (Paperless has no SCIM endpoint). `PAPERLESS_SOCIAL_AUTO_SIGNUP=true` handles SSO-first users.

## Portal Links (no changes)

- `/dashboard/docs` tab — already exists, fetches documents via `/api/me/documents`
- Root page service link — already links to `https://docs.{domain}`

## Deployment Steps (live system)

1. Set `PAPERLESS_OIDC_CLIENT_SECRET` in `/srv/platform/.env` (generate with `openssl rand -hex 32`)
2. Set `PAPERLESS_SECRET_KEY` in `/srv/platform/.env` if not already set
3. Restart Paperless to pick up new env: `docker compose restart paperless`
4. Call `POST /api/admin/reprovision-authentik` to create the Authentik provider
5. Verify SSO login works at `https://docs.{domain}`

## Verification

1. Fresh install: run `install.sh`, check `.env` contains both new secrets, complete bootstrap, verify `https://docs.{domain}` redirects to Authentik login
2. Live system: call reprovision endpoint, verify Authentik admin shows `paperless-ngx` application, attempt SSO login
3. User provisioning: create a user via portal admin, verify Paperless account + workflow + mail rule are created
